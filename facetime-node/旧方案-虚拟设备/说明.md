# 这些脚本已经不用了

验证阶段的产物。那时候的方案是**给 FaceTime 真实的虚拟设备**：

- `setup.sh` —— 装 Chrome、`v4l2loopback`（虚拟摄像头）、PulseAudio（两个虚拟声卡）、Xvfb、ffmpeg
- `call.sh` / `stop.sh` —— 起停一次通话
- `restart-cam.sh` —— 换头像后重推摄像头
- `check-audio.sh` —— 验音频双向通不通

**后来发现这一整套都不需要。** 既然能在页面加载前改写 `getUserMedia`，就可以直接
交给 FaceTime 一个自己造的流：声音来自 WebAudio，画面来自一块画着头像的 canvas。
已实测跑通，FaceTime 看不出区别。

于是节点的外部依赖从「Chrome + Xvfb + PulseAudio + v4l2loopback + ffmpeg」
缩成了「Chrome」（Linux 上多一个 Xvfb）。详见 [设计.md](../设计.md) 第 3 节。

## 为什么留着

两件事还没做完：

1. **新方案在 Linux 上还没实测。** 尤其是「浏览器窗口切到后台时 canvas 捕获轨
   被标成静音」这个问题 —— Xvfb 里没有「前台/后台」的概念，大概率不受影响，
   但没验证过。
2. 万一造流那条路在 Linux 上有别的毛病，这套是**验证过能用的退路**。

Linux 上实测通过之后，这个目录就可以删掉了。

## 已经按旧方案装过的机器怎么办

不用急着卸。新方案根本不碰这些东西，留着只占几十兆内存。确认新方案能用之后
再清理：

```bash
# 卸虚拟摄像头
sudo modprobe -r v4l2loopback
sudo apt remove -y v4l2loopback-dkms v4l2loopback-utils
sudo rm -f /etc/modprobe.d/facetime-vcam.conf /etc/modules-load.d/facetime-vcam.conf

# 卸虚拟声卡（重启后自动消失，不用卸 PulseAudio 本身）
pactl unload-module module-remap-source 2>/dev/null
pactl unload-module module-null-sink 2>/dev/null
```

Chrome、Xvfb、ffmpeg **不要卸** —— 前两个新方案还要用，ffmpeg 虽然节点不用了，
但 Uranus 本体要靠它处理语音和图片。

Windows 上装过 VB-CABLE 的，可以从「应用和功能」里卸掉，新方案不需要它。
