## 这是什么功能

用户在 iPhone 的 FaceTime 里创建链接、用 iMessage 发给角色，角色就用自己的声音
接电话。**真的 FaceTime**，接通后全程在 iPhone 原生界面里，不是在网页上画一个
通话框。

设计和所有决策的理由见 [设计.md](设计.md)，那份是完整的。这里只写「现在到哪一步」。

## 关键的架构决定（别推翻）

1. **节点是独立程序**。Uranus 跑在 CF Worker 或安卓上时起不了浏览器，所以这个
   功能天生两半。
2. **节点不持有任何密钥**。转写和合成都在 Uranus 那边做，节点只搬运音频。
3. **不用虚拟声卡/虚拟摄像头**。改写 `getUserMedia`，直接给 FaceTime 一个自造的
   流（声音来自 WebAudio、画面来自 canvas）。实测它看不出区别。连 ffmpeg 都不用。
4. **上下文、记忆、总结和发短信完全共用一套**。一接通就知道之前聊了什么，挂断
   后在 iMessage 里能接着聊。
5. **通话另开一条轻链路**，不走 `handleTurn`（那 700 行一多半只在发短信时成立）。
6. **收到链接先问角色接不接**，不直接入会。

暴露两件事（v1.19.3 修了）：

- 🔴 **开场白开头几个字被吞掉。** 这是 v1.19.1「提前合成」自己带出来的：
  原来接通后还要打一轮模型（8–25 秒），那段时间顺带把上行通道焐热了；

     Uranus 那边 `role.call.openingDelayMs` 可调。
  `test/shim.test.mjs` 里钉死了底噪那一条（幅度要在 0 到 0.01 之间）。
- 🔴 **Qwen3-ASR 一直 400**：`The dedicated task 'asr' ... does not support
  this input`。骂的不是音频，是我们多发的那条文字指令 ——
  `qwen3-asr-flash` 是专职任务，user 的 content **只许一条、只许
  `input_audio`**。语言改走顶层 `asr_options`。
  详见 `stt.js:sttQwen` 的函数头，那里记了完整的坑和文档链接。

**用户不再用 whisper 了**（中文听不清），现在中文这条路是 Qwen3-ASR。
界面上也改成推荐它了。

## 第三通（2026-10-13，202 秒 / 5–7 轮）结论

v1.19.0 的两项没验证效果（用户说延迟先不管了），这一通暴露的是**转写**：

转写出来的东西基本是坏的 —— 1500ms 的一句话只出「你」一个字，2640ms 出
「在家裡」三个字（还是繁体），「怎么」被认成「三者」。

**根子不在模型，在节点取声音那一步**（v1.19.1 修了）：
`fakemedia.mjs` 原来把 48kHz 的采样「每三个取一个」降到 16kHz ——
**抽取却不滤波**，8kHz 以上的频率全部折回语音频段变成噪声，而中文的
s/sh/x/c/ch/q 这些辅音能量大半在那上面。原来那行注释写着「最近邻重采样，
语音识别这个用途上够了」，那个判断是错的。

修法不是自己写低通，而是**另建一个 16kHz 的 AudioContext** 来采
（`createMediaStreamSource` 接进去时浏览器自己做带抗锯齿的重采样，
ratio 恒为 1）。为什么不直接把 `ac` 改成 16kHz：那条还要往 FaceTime 灌角色
的声音，整条压下去等于把角色音质也拉低。16kHz 上下文建不起来时退回
**窗口平均**（很糙的低通，但远好于最近邻）。

顺带做的：
- 说中文时自动给 whisper 一句简体提示词（它认中文默认偏繁体）
- 推荐模型从 `whisper-large-v3-turbo` 改成 `whisper-large-v3`
- 节点日志多记**音量**（峰值 / 有效值 dBFS）—— 下次转写不准时先看这个，
  能一眼分清是「声音太小」还是「模型该换」
- 「一直没接上对方的声音」的告警从 5 秒放宽到 20 秒（原来每通都报假警报）

另外两项：
- **接通瞬间就有话说了**：角色在 `[接受通话]` 后面写的那段话存进
  `callsession.js` 的 `greeting`，节点报 connected 时直接合成播出去
  （`callturn.js:runCallSay`，不打模型）。那段话**不发短信**。
- **修**：挂断后那条「通话结束 · N 秒 · N 轮」原来会 `sendSystem` 一遍，
  真的发到用户的 iMessage 里了。现在只 `appendTurn` 进存档。

### 延迟账（这一通的真实数字）

一轮从「对方说完」到「第一声回话」，拆开是：

| 哪一段 | 耗时 |
|---|---|
| VAD 判断说完了 | 0.7s（`silenceEndMs`） |
| 转写（Groq whisper） | **0.24–0.33s** |
| 攒提示词（世界书 + 记忆检索） | 1.0–1.4s |
| **模型** | **7.8s / 8.5s / 8.9s / 9.1s / 10.2s / 10.7s / 24.9s** |
| 第一句 TTS（ElevenLabs） | 0.7–1.4s |

**模型占了九成。** 原因是 `gemini-3.8-flash` 在思考：日志里 `completion_tokens`
是 611–2212，而实际说出来的只有 23–67 字，差的全是 reasoning token。
加上每轮 prompt 都是 19k token。

v1.19.0 做了下面 2 和 3，**还没实测过效果**：

1. **换个不思考的模型** —— 最省事，用户自己在「通话用哪个模型」里改。
   这条永远是最彻底的解。
2. ✅ **「通话时让模型少思考」开关**（`role.call.noThinking`，默认开）。
   发 `reasoning_effort` + `enable_thinking`，从 `none` 开始要，上游嫌哪一档
   不行就降一档（none → minimal → low），降到底脱掉字段。梯子和判据在
   `llm.js:THINKING_LADDER` / `rejectsThinking`，原生 Gemini 翻成
   `thinkingConfig.thinkingLevel`（`apitype.js:toGeminiBody`）。
   **刻意不受 `GEMINI_STRICT` 管** —— 那条说的是「温度那几个采样参数一个都
   不能带」，而 `reasoning_effort` 恰恰是 Gemini 3 认的那个字段，真正需要关
   思考的也正是这批模型，一起挡掉等于这个开关对它们永远无效。
   注意 **Gemini 3 一代关不掉**，只能压到最低档（3.7/3.8 的 Flash 连
   `minimal` 都不认，会落到 `low`），所以这个开关减轻不等于解决。
3. ✅ **通话能单独挂世界书**（`role.call.worldBookRefs`）。
   **空 = 跟着线上走**，和线下那份（空 = 一本都不挂）规矩相反，解析在
   `prompt.js` 里 `callBooks` 那段。**记忆和上下文照旧全带**，没动。

### v1.20.0 做了的

- ✅ **控制台「通话」一栏**（`console.jsx:CallPanel`）：节点在不在线、正在打的
  那通（能挂断）、最近 20 通。记录存在 `data/calls.json`（`calllog.js`），

  只在通话中每 3 秒轮询，平时不打空轮询。
- ✅ **同机的节点不用配对码**（`callNode.trustLocal`，默认开）。门禁在
  `callapi.js:checkSecret` / `isLoopback`，**是多一条路、不是换一条路** ——
  远程节点照旧用密钥，已配对的不会断。认「本机」要同时满足：
  socket 地址是回环（含 `::ffff:127.x`）、没有任何转发头（防 nginx 反代后面的
  公网请求）、没有 `Origin` / `Sec-Fetch-Site`（防本机浏览器里的网页 CSRF）、
  `Host` 是回环字面量（防 DNS 重绑定；**要认完整四段**，`127.0.0.1.evil.example`
  是合法域名，前缀匹配会放它进来 —— 测试抓到过）。
  节点那头 `isLocalUranus` 决定没密钥能不能起，`install-service.sh` 没有
  config.json 也照装。`scripts/test-callapi.mjs`（47 条）钉门禁和记录。
  **已知盲区**：frp / ssh 隧道这类纯端口转发不带任何标记，看起来和本机一样 ——
  界面上写了「用这类的请关掉这个开关」。

### 未发布：听语气、听背景声音（角色栏两个开关，默认都开）

- ✅ **语气**：Qwen3-ASR 每次都顺带回情绪标签（`message.annotations[].emotion`，7 种），
  以前被扔掉了，现在 `stt.js:qwenEmotion` 读出来。平静的不报，其余变成
  `[{{user}}的语气：开心]` 贴在那句话前面。**不多花钱、不多等**。别家专门的转写不给情绪。

- ✅ **背景声音**：用角色的「听音」模型**在后台**听（`callturn.js:listenAmbience`），

## 实测踩过的坑（别再踩）

### FaceTime 页面

- **入会是三屏**：姓名（只有「继续」）→ 准备（才有「加入」和设备按钮）→ 等待
- **设备是按钮不是下拉框**，点开弹菜单再点一项
- **`aria-pressed` 的语义靠不住，而且两个开关还不一致**：同一次通话里两个都开着
  时，摄像头是 `true`、麦克风是 `false`。所以改成读真实的 `track.enabled`
- **关菜单要点「关闭菜单」**，Escape 不管用，而且要反复点到没有为止
- 控件全是 `<ui-button>` 这类自定义元素，按 `role=button` 找，别写死标签名
- 页面语言跟系统走（用户那台是中文），关键词中英都要列

### 造流

- canvas 要**挂进 DOM**（游离在外合成器可能不处理）
- 帧要**手动 `requestFrame()`**（`captureStream(fps)` 的变化判断不在我们手里）
- 噪点要**够明显**（`rgba(...,0.02)` 会被 H.264 降噪抹平）

### 写代码时

- `fakemedia.mjs` 和 `facetime.mjs` 里注进页面的那几段是**模板字符串**，
  注释里写一个反引号就会截断它，而报错指向的是一行注释。已有测试钉死
  （`test/shim.test.mjs`）
- 这个仓库的测试是 `scripts/test-*.mjs`，自己 `check()` 计数，不用测试框架

### VPS 运维

- 仓库属主是 `admin`，Node 是 nvm 装在 `/home/admin/.nvm/` 下的 ——
  用 root 跑 npm 会留下 root 的文件，之后 admin 写不了。都用
  `sudo bash scripts/update-vps.sh`，它自己处理
- 更新完要**硬刷新浏览器**，旧 JS 会留在缓存里

## 怎么测一通电话

### 1. 确认都是最新的

```bash
sudo bash /opt/imessage/scripts/update-vps.sh && sudo systemctl restart uranus-facetime
```

然后硬刷新浏览器（Ctrl-Shift-R）。

**务必核对版本号**（控制台页脚）。踩过一次：以为更新了，实际跑的还是上一版，
于是「修好的东西还是老样子」，白排查半天。脚本会在最后打一行
`更新完成：<提交>`，和 `git log --oneline -1` 对一下最稳。

### 2. 控制台上确认三处

- **连接 → 语音转文字**：**中文用阿里云 Qwen3-ASR**（模型
  `qwen3-asr-flash`，地址留空 = 官方），**语言选中文**（默认就是）。
  whisper 那条的中文明显更差，v1.19.3 起界面上也不推荐它了
- **角色 → 接 FaceTime 通话**：开关开着、通话节点开着。节点和 Uranus 同机的话
  不用配对密钥（v1.20.0 起），在别的机器上才要
- **同一栏的「通话用哪个模型」**：挑一个**不带 thinking、不限流**的。
  上次那通撞了 429（一分钟 10 次），通话一轮要打好几次很容易触顶。
  第二通用的 `gemini-3.8-flash` 没限流，但它**在思考** —— 一轮等 8–25 秒，
  见上面「延迟账」

### 3. 开两个窗口盯日志

```bash
journalctl -u uranus-facetime -f
```

控制台的日志页另开一个。

### 4. 打

iPhone 的 FaceTime → 创建链接 → 用 iMessage 发给那个角色 → iPhone 上点「允许」。

### 5. 重点看这四件事

| 看什么 | 怎么判断 |
|---|---|
| **少思考起作用了吗**（v1.19.0） | 控制台日志里那行 `回了 N 字，耗时 Nms` 该明显短于 8 秒。`token 用量` 里的 `completion_tokens` 该贴近实际字数（之前是 611–2212 对 23–67 字）。要是出现「不收 reasoning_effort=…，降到 … 重打」，说明那个模型不认这一档 —— 降完还是慢就换模型 |
| **通话世界书挑过之后** | 日志里「世界书命中 N 条」该变少，`prompt_tokens` 该从 19k 掉下来 |
| **还会不会自己打断自己** | 节点日志里的「对方插话了」应该只在你真的插话时出现。角色说话时自己触发就是没修好 |
| **挂断识别得了吗** | 你挂断之后，节点日志该出现「对方挂断了（WebRTC 连接断了…）」。没有这行、节点还在跑就是没修好 |
| **转写准不准**（v1.19.1 的重点） | 节点日志里「对方说了一段 2640ms」后面跟的转写该是**完整的一句话**，不是三个字。还要看那行新加的音量：峰值低于 -30dBFS 说明声音太小（那是采集的事，不是模型的事）。输出该是简体 |
| **接通后第一句** | 节点日志该是「接通了，先等 1500ms 让语音通道热起来再开口」，然后出声。**头几个字不该被吞**（v1.19.3 加了底噪 + 这个延迟）。还吞就把角色那栏的「接通后等多久再开口」调到 2000～2500 |
| **挂断后不该收到短信** | iMessage 里**不该**出现「通话结束 · N 秒 · N 轮」。控制台日志里有「记进聊天记录：通话结束…」是对的 |
| **流畅度** | 一轮下来几秒？说话连不连贯？ |

### 6. 挂断后

```bash
journalctl -u uranus-facetime -n 40 --no-pager
```

把这段和控制台的日志一起贴出来。
