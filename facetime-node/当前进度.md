## 这是什么功能

用户在 iPhone 的 FaceTime 里创建链接、用 iMessage 发给角色，角色就用自己的声音
接电话。**真的 FaceTime**，接通后全程在 iPhone 原生界面里，不是在网页上画一个
通话框。

设计和所有决策的理由见 [设计.md](设计.md)，那份是完整的。这里只写「现在到哪一步」。

## 关键的架构决定（别推翻）

1. **节点是独立程序**。Uranus 跑在 CF Worker 或安卓上时起不了浏览器，所以这个
   功能天生两半。
2. **节点不持有任何密钥**。转写和合成都在 Uranus 那边做，节点只搬运音频。
3. **不用虚拟声卡/虚拟摄像头**。改写 `getUserMedia`，直接给 FaceTime 一个自造的
   流（声音来自 WebAudio、画面来自 canvas）。实测它看不出区别。连 ffmpeg 都不用。
4. **上下文、记忆、总结和发短信完全共用一套**。一接通就知道之前聊了什么，挂断
   后在 iMessage 里能接着聊。
5. **通话另开一条轻链路**，不走 `handleTurn`（那 700 行一多半只在发短信时成立）。
6. **收到链接先问角色接不接**，不直接入会。

## 第二通实测（2026-10-13，226 秒 / 8 轮）结论

**整条链路跑通了。** 之前列的三项「待验证」全部通过：

- ✅ **自己打断自己** —— 修好了。三次「对方插话了」都在用户真的出声的那一秒，
  角色自己说话时没触发。用户的说法是「语音流畅了」
- ✅ **挂断检测** —— 日志里是「对方挂断了（WebRTC 连接断了（closed））」，
  也就是 v1.17.0 新加的那个判据真的命中了（原来那两个仍然没命中）
- ✅ **Xvfb 里 canvas 捕获轨不会被标静音** —— 全程没掉
- ✅ 头像自动拿到了（37KB）
- ✅ 端到端联调（三个口子）跑通
- ✅ 第一次有完整的 iMessage 通话小结发回来

### 这一通暴露的问题

- 🔴 **转写把中文认成别的语言**（v1.18.2 修了）。不给语言的话 whisper 每段
  各猜各的，8 轮里出了冰岛语、韩语 ×3、俄语。现在「连接 → 语音转文字」里
  有「说的是哪种语言」，默认中文
- 🔴 **延迟全在模型身上**，见下一节
- 🟡 **节点数 6 轮、Uranus 数 8 轮**。差的两轮是「45 秒没说话」的提醒和
  通话小结那条 —— 两边数的不是一回事。不影响功能，但小结里写的轮数以哪边
  为准要定一下
- 🟡 接通后 9 秒有一条 `音频 一直没接上对方的声音 —— 转写这条路是断的`，
  然后就正常了。是接通瞬间对方的音频轨还没挂上来，**告警放早了**，
  该等到第一次真的要转写时还没有轨再报
- 🟡 挂断时 `没找到挂断按钮，直接关浏览器`。结果是对的（本来就要关），
  但这条 WARN 每通都会出现，要么找对按钮要么降成 INFO

### 延迟账（这一通的真实数字）

一轮从「对方说完」到「第一声回话」，拆开是：

| 哪一段 | 耗时 |
|---|---|
| VAD 判断说完了 | 0.7s（`silenceEndMs`） |
| 转写（Groq whisper） | **0.24–0.33s** |
| 攒提示词（世界书 + 记忆检索） | 1.0–1.4s |
| **模型** | **7.8s / 8.5s / 8.9s / 9.1s / 10.2s / 10.7s / 24.9s** |
| 第一句 TTS（ElevenLabs） | 0.7–1.4s |

**模型占了九成。** 原因是 `gemini-3.8-flash` 在思考：日志里 `completion_tokens`
是 611–2212，而实际说出来的只有 23–67 字，差的全是 reasoning token。
加上每轮 prompt 都是 19k token。

v1.19.0 做了下面 2 和 3，**还没实测过效果**：

1. **换个不思考的模型** —— 最省事，用户自己在「通话用哪个模型」里改。
   这条永远是最彻底的解。
2. ✅ **「通话时让模型少思考」开关**（`role.call.noThinking`，默认开）。
   发 `reasoning_effort` + `enable_thinking`，从 `none` 开始要，上游嫌哪一档
   不行就降一档（none → minimal → low），降到底脱掉字段。梯子和判据在
   `llm.js:THINKING_LADDER` / `rejectsThinking`，原生 Gemini 翻成
   `thinkingConfig.thinkingLevel`（`apitype.js:toGeminiBody`）。
   **刻意不受 `GEMINI_STRICT` 管** —— 那条说的是「温度那几个采样参数一个都
   不能带」，而 `reasoning_effort` 恰恰是 Gemini 3 认的那个字段，真正需要关
   思考的也正是这批模型，一起挡掉等于这个开关对它们永远无效。
   注意 **Gemini 3 一代关不掉**，只能压到最低档（3.7/3.8 的 Flash 连
   `minimal` 都不认，会落到 `low`），所以这个开关减轻不等于解决。
3. ✅ **通话能单独挂世界书**（`role.call.worldBookRefs`）。
   **空 = 跟着线上走**，和线下那份（空 = 一本都不挂）规矩相反，解析在
   `prompt.js` 里 `callBooks` 那段。**记忆和上下文照旧全带**，没动。

测试：`node scripts/test-callthinking.mjs`（33 条）

## 实测踩过的坑（别再踩）

### FaceTime 页面

- **入会是三屏**：姓名（只有「继续」）→ 准备（才有「加入」和设备按钮）→ 等待
- **设备是按钮不是下拉框**，点开弹菜单再点一项
- **`aria-pressed` 的语义靠不住，而且两个开关还不一致**：同一次通话里两个都开着
  时，摄像头是 `true`、麦克风是 `false`。所以改成读真实的 `track.enabled`
- **关菜单要点「关闭菜单」**，Escape 不管用，而且要反复点到没有为止
- 控件全是 `<ui-button>` 这类自定义元素，按 `role=button` 找，别写死标签名
- 页面语言跟系统走（用户那台是中文），关键词中英都要列

### 造流

- canvas 要**挂进 DOM**（游离在外合成器可能不处理）
- 帧要**手动 `requestFrame()`**（`captureStream(fps)` 的变化判断不在我们手里）
- 噪点要**够明显**（`rgba(...,0.02)` 会被 H.264 降噪抹平）

### 写代码时

- `fakemedia.mjs` 和 `facetime.mjs` 里注进页面的那几段是**模板字符串**，
  注释里写一个反引号就会截断它，而报错指向的是一行注释。已有测试钉死
  （`test/shim.test.mjs`）
- 这个仓库的测试是 `scripts/test-*.mjs`，自己 `check()` 计数，不用测试框架

### VPS 运维

- 仓库属主是 `admin`，Node 是 nvm 装在 `/home/admin/.nvm/` 下的 ——
  用 root 跑 npm 会留下 root 的文件，之后 admin 写不了。都用
  `sudo bash scripts/update-vps.sh`，它自己处理
- 更新完要**硬刷新浏览器**，旧 JS 会留在缓存里

## 怎么测一通电话

### 1. 确认都是最新的

```bash
sudo bash /opt/imessage/scripts/update-vps.sh && sudo systemctl restart uranus-facetime
```

然后硬刷新浏览器（Ctrl-Shift-R）。

### 2. 控制台上确认三处

- **连接 → 语音转文字**：填了 Groq（地址 `https://api.groq.com/openai/v1`，
  模型 `whisper-large-v3-turbo`），**语言选中文**（默认就是）
- **角色 → 接 FaceTime 通话**：开关开着、通话节点开着、有配对密钥
- **同一栏的「通话用哪个模型」**：挑一个**不带 thinking、不限流**的。
  上次那通撞了 429（一分钟 10 次），通话一轮要打好几次很容易触顶。
  第二通用的 `gemini-3.8-flash` 没限流，但它**在思考** —— 一轮等 8–25 秒，
  见上面「延迟账」

### 3. 开两个窗口盯日志

```bash
journalctl -u uranus-facetime -f
```

控制台的日志页另开一个。

### 4. 打

iPhone 的 FaceTime → 创建链接 → 用 iMessage 发给那个角色 → iPhone 上点「允许」。

### 5. 重点看这四件事

| 看什么 | 怎么判断 |
|---|---|
| **少思考起作用了吗**（v1.19.0） | 控制台日志里那行 `回了 N 字，耗时 Nms` 该明显短于 8 秒。`token 用量` 里的 `completion_tokens` 该贴近实际字数（之前是 611–2212 对 23–67 字）。要是出现「不收 reasoning_effort=…，降到 … 重打」，说明那个模型不认这一档 —— 降完还是慢就换模型 |
| **通话世界书挑过之后** | 日志里「世界书命中 N 条」该变少，`prompt_tokens` 该从 19k 掉下来 |
| **还会不会自己打断自己** | 节点日志里的「对方插话了」应该只在你真的插话时出现。角色说话时自己触发就是没修好 |
| **挂断识别得了吗** | 你挂断之后，节点日志该出现「对方挂断了（WebRTC 连接断了…）」。没有这行、节点还在跑就是没修好 |
| **转写质量和速度** | 不该再出现六段式报告（「1) 原话转写：… 2) 语言：…」）。Groq 该在一秒内返回 |
| **流畅度** | 一轮下来几秒？说话连不连贯？ |

### 6. 挂断后

```bash
journalctl -u uranus-facetime -n 40 --no-pager
```

把这段和控制台的日志一起贴出来。
